## 二、屎山画像：这平台到底「脏」在哪

不是代码不会写，而是**同一种模式被复制粘贴到十几处，且没有单一出口**。按严重度排：

1. **God Class（最重）**：`Main.java` 一个类装了 40+ 个接口处理函数、鉴权、计分、计时、状态机、静态文件服务。任何一次改动都要在 2 300 行里翻。这是本轮唯一没有动结构的地方——拆包会牵动所有路由注册，风险大于收益，留作后续专项。
2. **重复样板**：鉴权守卫 13 份、口令校验 5 份、限流 3 份、禁言 2 份、`ok:true` 9 份。全部已收口。
3. **魔法值**：正确性用例数 `5` 在判罚、强制结束两处写死（已改）；禁言档位、冷却毫秒、保留条数已有常量，反而还好。
4. **死代码**：`commentsAfter`（早期增量拉取方案遗留）、`cleanNick`（观众昵称方案改成「观众37」后遗留）、`lastViewerAt`/`VIEWER_COOLDOWN_MS`（按 IP 限流的旧方案遗留）。已删。
5. **CSS 层叠式重复**：`.discuss-panel` 定义两次、`.comment-input` 两次、`.discuss-tip` 两次，靠书写顺序决定最终样式。已合并。
6. **前端巨型单文件**：`watch.html` 1 763 行、`app.js` 1 164 行，内含轮询定时器、渲染、交互全套。可读性差但内聚，拆文件收益低于风险，未动。
7. **命名不统一（轻）**：`staffComment` / `adminCommentPost` / `commentsApi` 三条发言通道，语义靠注释区分；`/api/admin/user-op` 与 `/api/judge/user-op` 各自一半权限。本轮只收敛实现，未改路由（改路由要同步 4 个前端文件，属于重构专项）。

## 三、bug 发现与改进看法

### 已修复（本轮或本轮前）

- **A. 观赛「实时代码」根本没跑起来**（本轮发现并修）。`watch.html` 里 `startCodePoll()` 有定义、`stopCodePoll()` 有调用，但 `startCodePoll` 全文件零调用点——详情卡打开后从没启动 2 秒轮询，所以「实时」区永远是「该选手尚未上报代码」。这类 bug 不会报错、不会 500，只是功能静默失效，最难被发现。修法：详情卡渲染完立刻 `startCodePoll(p.no)`，返回概览时已有的 `stopCodePoll()` 兜住。
- **B. 后台账号表每行被撑到 100px+**（上一轮修）。根因是 `.utags`/`.uops` 把 `display:flex` 加在 `<td>` 上，表格单元变成块级盒，行高失控。教训：`display` 不要改写表格单元的默认值。
- **C. 授予/撤销管理员稳定报「服务异常：data\state.tsv」**（上一轮修）。`writeState` 直接覆盖写，多请求并发抢句柄，Windows 抛 IOException。改成先写 `.tmp` 再 `ATOMIC_MOVE`，并加 `synchronized`。

### 尚未修复，建议按优先级处理

| 级别 | 问题 | 说明与建议 |
|------|------|------------|
| P0 | `results.tsv` / `comments.tsv` 仍是「直接覆盖写」 | 只有 `state.tsv` 做了原子替换。交卷与发评论是同进程同步方法，平时不会撞，但一旦写盘中途异常（磁盘满、被杀进程），文件会被截断成半截，等于整届成绩丢失。建议把 `writeState` 的 tmp+move 抽成一个 `atomicWrite(Path, String)`，三个文件都走它。 |
| P0 | `sessions` 只增不减 | `auth()` 里只清理 `killedTokens`，`sessions` 没有过期时间。比赛当天几百个登录无感，长期跑会缓慢涨内存。建议给 Session 加 `lastSeen`，`auth` 时顺手踢掉超过 12 小时未活动的会话。 |
| P1 | 观看接口每秒重算全量 | `/api/watch` 每次遍历全部选手并读 `store.state`（synchronized 全表）。65 人没问题，上百人 + 多观众轮询会出现锁竞争。建议把「选手实时快照」做成一个 1 秒刷新的内存视图，接口只读快照。 |
| P1 | 三条发言通道语义重叠 | `/api/comments`（学生/观众）、`/api/admin/comment-post`（管理员）、`/api/staff/comment`（裁判/总管）。权限、限流、敏感词各写一遍，将来加「助教」角色又要复制。建议合成一条 `/api/say`，身份由 token 决定，`role` 由服务端算——前端只传 `text` + `kind`。 |
| P2 | `Main` 该按域拆分 | 建议 `Auth` / `Contest` / `Comments` / `Watch` / `Admin` 五个 handler 类，路由注册仍留在 `Main`。拆的时候先补一层接口级回归脚本（本轮已经有一个可复用的 `Check.java` 雏形）。 |
| P2 | 无任何自动化测试 | 现在全靠手点。最低成本方案：保留一个 `Check.java`（纯 `HttpClient` + 断言，零依赖），`start.bat` 之后跑一遍，覆盖登录/权限/发言/开赛/结束五条主链。 |
| P2 | 图形验证码、旧 `backend\src\app.js` 副本、旧 25 分制历史成绩 | 三项仍待定：验证码会增加登录摩擦，内测 65 人阶段可先不做；`backend\src\app.js` 不参与运行，建议直接删；`results.tsv` 里 25 分制旧记录的显示不一致，建议一次性清洗或整体清空重开。 |

### 关于「观众端不延迟」这条需求

结构上已经成立：观赛页没有 3 秒延迟，代码 2 秒一轮、状态 1.5 秒一轮，靠的是**发言侧拦截**（敏感词双表 + 赛中禁发弹幕 + 阶梯禁言）而不是拖时间。本轮修好的 A 项正是让「不延迟看代码」真正生效的那一环——之前延迟为零，是因为根本没在拉。
