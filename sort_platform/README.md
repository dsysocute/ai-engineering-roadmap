# 排序算法测评平台

大数据专业排序算法比赛用的判题系统。选手在网页里写代码、测试运行、交卷，系统自动判正确性与效率，给出成绩、排行榜，并支持观众观赛、课堂讨论、弹幕与裁判控制。

## 一、运行环境

- **JDK 17**（不是 JRE）。判题要调用 `javac`，只装 JRE 会在点「测试运行」时报找不到编译器。
- 端口默认 `8080`，被占用可以用环境变量改：`set PORT=8090`（Windows）/ `export PORT=8090`（Linux）。
- 不需要数据库、不需要 Maven、不需要 Spring。

## 二、启动

**Windows**：双击 `start.bat`（先 `javac` 编译，再以 `backend\src` 为 classpath 启动）
**Linux / Mac**：`./run.sh`

启动后控制台会打印两个地址：

- 本机访问 `http://localhost:8080`
- 同学访问 `http://本机IP:8080`（同一局域网，防火墙要放行 8080）

| 项目 | 内容 |

### 管理员（管观众与选手）

浏览器打开 `/admin`。管理员由总管在学生账号中授予，**口令默认就是被授权人的学号**，可在后台自助修改（原口令 + 新口令）。被授予后自动退出选手名单，学生账号只能以观众身份观赛，不参与本场排名（页面会提示原因）。

- 能：禁言/解禁选手和观众、删评论、看成绩、检举裁判违规（自动进总管事务台）、处理「不当言论」举报和「禁言」申诉。
- 不能：开赛、强制结束、判违规、封号、设置管理员或裁判、禁言裁判/管理员。

主管理员（教师）账号留空、口令 `sort2026#admin`（启动前可用环境变量 `ADMIN_PASS` 改）。

### 裁判（控制比赛，同学中的高级管理员）

裁判不是一套独立账号，而是**总管从学生里指定的一位同学**，全平台只能有一位（`data/state/users.tsv` 的 `judge.user`），换人即撤下原裁判，旧裁判令牌立即作废。被指定后自动退出选手名单，只能以观众身份观赛，不参与本场排名。

浏览器打开 `/judge`，输入**裁判口令**登录。裁判口令与该同学的学生登录密码是**两套**：同一个人，用学号 + 学生密码可以正常答题，用裁判口令才能进裁判控制台。裁判口令默认 `abc2511298`（环境变量 `JUDGE_PASS`），页面可自助修改；总管在总控台也能重置。

- 能开赛、强制结束；判罚违规（终止该选手本场，成绩记 0 分并留档事由）。
- 只能处理「违规」类举报与「违规」类申诉，**没有禁言权限**（禁言归管理员），不能封号，不能设置管理员。
- 可以带令牌进入观赛页发言，头衔显示「裁判」。
- 未指定裁判时，裁判页会提示「还没有指定裁判，请总管在总控台指定一位同学」，无法登录。
- 被总管封号即撤下裁判身份、退出选手名单，只能以观众身份登录。

### 总管（开发者）

浏览器打开 `/super`，账号 `supervisor`、口令 `super2026`（环境变量 `SUPER_USER` / `SUPER_PASS`，页面可自助改，落 `data/state/users.tsv` 的 `super.pass`）。总管**不在 65 个学号里**，是独立后台身份。

- 唯一的「设置/撤销裁判」「设置/撤销管理员」入口；裁判全平台唯一，换人即原裁判令牌作废。
- 可重置学生登录密码（留空回 `123456`）；也可重置管理员/裁判的控制台口令（留空回默认：管理员回学号，裁判回 `abc2511298`），重置后已发放的控制台令牌立即作废。
- 可禁言/解禁、封号/解封、判违规、处理全部举报与申诉、查看赛事概览，发言头衔显示「总管」。
- 封号时会记 `banreason.<学号>`（总控台弹窗可填原因）；接口若带 `caseId` 还会落 `bancase.<学号>`，解封一并清除。
- 封管理员或裁判时，会同时撤掉其管理/裁判身份与口令，并退出参赛名单，降为观众。

## 三之二、处分与举报申诉体系

所有处理都在独立的事务台 `/case`（按身份登录，或带令牌 `?st=` / `?jt=` / `?at=` 直进）。案件落 `data/cases.tsv`，保留最近 200 条。

| 类型 | 来源 | 谁能处理 |
|---|---|---|
| 违规 `violation` | 选手/观众举报，或裁判直判 | 裁判、总管 |
| 不当言论 `speech` | 选手/观众举报 | 管理员、总管 |
| 禁言申诉 `mute` | 被禁言者申诉 | 管理员、总管 |
| 封号申诉 `ban` | 被封号者申诉 | 总管 |
| 工作人员违规 `staff` | 管理员举报裁判/管理员 | 总管 |

- 举报入口：选手/观众右上角头像菜单「我要举报」，选人 + 类型 + 理由；不能举报自己，同人同因的待处理举报不重复入库。
- 申诉入口：头像菜单「我要申诉」，系统按当前状态自动判定是禁言、封号还是违规申诉。
- 处理页显示涉及账号、举报人/申诉人、理由、处理人、处理说明；「通过并生效」会立刻执行：违规 → 该选手本场记 0；不当言论 → 按阶梯禁言；禁言申诉 → 解禁；封号申诉 → 解封（恢复选手身份需重新登录）；工作人员违规 → 仅留档（不自动撤职、不自动封号）。
- 工作人员违规案件对总管额外显示「通过并封号」：一次操作同时留档、撤职、封号并写 `bancase`，仍需人工点击，不是自动处罚。
- 违规申诉通过分两种情况：
  - **判罚前已经交过卷**：恢复判罚前的成绩（判罚时把该账号成绩整行存成 `violprev.<学号>` 的 Base64 TSV 快照，申诉通过后写回）。
  - **判罚时还在答题**：不恢复 0 分，而是**放回比赛区复赛**——按「判罚那一刻本场还剩多少时间」给他个人倒计时（被罚期间和申诉等待的时间不算他的），已用时长接着原来的走；整场结束后也能继续交卷，照常判分并计入名次。复赛窗口用完后按当前代码收卷。
- 开新一场、删除单人成绩时会清掉快照与复赛状态，避免旧场次成绩被还原。
- 旧的两套举报通道（管理员「检举选手」、裁判「检举收件箱」）已删除：/api/admin/report、/api/judge/reports 只作为兼容入口转成 /case 里的案件，页面统一跳 /case。
- 被封号账号仍可登录，但强制为观众，只能观赛与申诉，不能参赛、不能发言。

## 三之三、账号菜单

选手端和观赛页右上角有一个圆形虚拟头像（显示学号后两位），点开依次是：修改ID（只改显示昵称，不改学号）、修改密码、我要举报、我要申诉、登出账户。

**工作人员视角**：裁判 / 管理员从控制台点「进入观赛」时，头像显示**自己的学号**（裁判=被指定的学号、管理员=被授予的学号）；总管是独立账号，头像显示「总管」。工作人员视角不会再借用浏览器里残留的学生会话。

**多标签页**：登录态按标签页隔离，同一个浏览器可以开多个标签页分别用「选手 / 观众 / 另一个学号」登录，互不覆盖；刷新页面不会改变本标签页的身份。新开的标签页默认继承最后一次登录的身份；从选手端点「观看其他选手」打开的观赛页会自动带上当前身份。

「我要举报」的对象列表按「选手 → 观众」分组，每 3 秒自动刷新，名单里能看到谁正在参赛、谁在线；自己和管理员/裁判不会出现在学生的可举报列表里。

## 四、判题规则

总分 100：

| 项目 | 满分 | 规则 |
|---|---|---|
| 正确性 | 60 | 五组数据全过才给，错一组直接 0 分 |
| 编码用时 | 20 | 从点「开始」到点「结束」，40 分钟内满分，之后分段线性递减，超 120 分钟 0 分 |
| 算法效率 | 20 | 与内置归并排序比耗时，按比值分段折算，同一台机器不用重调档位 |

正确性用例：1000 随机、10000 随机、10000 已排序、10000 完全逆序、10000 大量重复。
效率用例：100000 随机 / 已排序 / 逆序，每组热身 3 次、测 5 次取中位数。

效率评测在后台线程执行：异常、超时或无代码快照都会落成 0 分并标记完成，不会永远停在「测算中」；服务重启时会扫描「正确但未完成效率评测」的记录自动补跑。

## 五、赛事流程

1. 选手/观众登录，选手自动进入观赛列表。
2. 裁判在控制台填「本场时长（分钟，默认 120，可设 1~600）」再点「开启比赛」→ 全体端 10 秒倒计时 → running；各端顶部显示「剩余 HH:MM:SS」，最后 5 分钟变红。
3. running 期间：选手可作答、可放弃（提交白卷），不能中途退赛；选手侧讨论区与弹幕区上锁（交卷后解锁）；观众可评论、可发弹幕，含提示词会被拦。
4. 所有选手交卷、倒计时到 0、或裁判强制结束 → finished；选手交卷后解锁讨论区、切换到观赛视角，身份显示不变。
5. 倒计时到 0 时自动收卷：未交卷选手按当前编辑器里的代码判分（没写过代码的记白卷），编码用时按截止时刻封顶，不会多算；`contest.endAt` 记的就是截止时刻。
6. 赛后：统一讨论区开放（全局单一大评论区），弹幕恢复。

## 六、防作弊

- 静态扫描：出现 `Arrays.sort`、`Collections.sort`、`Stream.sorted`、`System.exit`、`ProcessBuilder`、`new Thread`、`new File`、`Socket`、`URL`、`Class.forName`、`reflect` 直接判违规。
- 选手代码跑在独立子进程里，超时直接 kill，内存上限 256MB。
- 校验不只看升序，还比对元素集合，防止交一个写死的有序数组。
- 计时以后端为准，前端只负责显示。
- 发言侧拦截：敏感词双表（提示类只拦不计数，辱骂类命中计违规并按 30 秒→5 分钟→1 小时→1 天→10 年逐档禁言，24 小时无违规清零）；赛中弹幕含提示词会被拦；内置 CD：评论 0.5 秒、弹幕 1.5 秒、快捷消息 3 秒。
- 观赛页不设延迟：观众看到的就是当前状态，靠发言拦截而不是拖时间防止递答案。

## 七、数据存在哪

| 文件 | 内容 |
|---|---|
| `data/results.tsv` | 成绩主表，14 列，重启不丢；表头为 `#v2`，读入时按文件版本决定是否启用旧制折算。旧 12 列自动补 `codingSeconds/runMillis=0`，无 `#v2` 的旧文件里 25 分制行（无该列且分数/效率 ≤25）×4 折算，越界分数不进排行榜 |
| `data/results.csv` | 同上导出的 Excel 友好版，双击可排序 |
| `data/comments.tsv` | 讨论区与弹幕，7 列（id / time / role / username / no / text / kind） |
| `data/state/contest.tsv` | 赛事状态（`contest.*`） |
| `data/state/users.tsv` | 报名名单、管理员名单、裁判归属（`judge.user`）、口令与密保、开始时刻（`start.*`）、昵称（`nick.*`） |
| `data/state/punish.tsv` | 禁言（`mute.*`）、封号（`ban.*`）、违规记录（`violation.*`）、判罚前成绩快照（`violprev.*`） |
| `data/state.tsv` | 升级前的旧大表；首次启动自动读入并迁到上面三个文件，之后只留认不出的键 |
| `data/cases.tsv` | 举报/申诉案件，14 列（id / kind / type / target / targetNo / reporterRole / reporter / reporterNo / reason / status / handler / handledAt / note / createdAt） |

## 八、目录结构

```
sort_platform/
├─ backend/src/          后端 20 个类，按域拆分：
│                        Main（启动/路由/静态文件）· App（全局状态与共用工具）· Http（请求解析与 JSON 响应）
│                        AuthApi / PlayApi / WatchApi / CommentApi / AdminApi / JudgeApi / SuperApi / CaseCenter（接口分域）
│                        Store / JudgeEngine / JudgeRunner / Checker / CompileService / ScoreCalculator / Json / MergeSortRef / SortStrategy
├─ frontend/             index.html / app.js / session.js / avatar.js / style.css / watch.html / admin.html / judge.html / super.html / case.html
├─ data/                 成绩与状态（运行后自动生成）
└─ start.bat / run.sh    启动脚本
```

> 拆分约定：接口类都 `extends App`，直接复用 `App` 里的静态状态与工具方法（没有实例、没有依赖注入），
> 调用方式与拆分前一致；`Main` 只负责启动、路由和静态文件。`CaseCenter` 里的 `Main.xxx` 调用照常可用（继承自 `App`）。

## 九、同学怎么交代码

在网页右边编辑器里写一个类 `Solution`，实现 `SortStrategy`：

```java
public class Solution implements SortStrategy {
    @Override
    public void sort(int[] arr) {
        // 在这里写排序
    }
}
```

写完点「测试运行」看有没有报错，确认没问题点「结束并交卷」。交卷后代码锁定，不能改。
