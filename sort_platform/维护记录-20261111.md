| # | 问题 | 根因 | 修法 | 实测验证 |

## 二、验证记录

- **编译**：JDK 17（`ms-17.0.20.1`）`javac -encoding UTF-8` 全量通过，exit 0；同时把 `.class` 重新编译进 `backend/src`，避免有人绕过 `start.bat` 直接 `java -cp backend/src Main` 跑到旧版本。
- **前端语法**：`node --check` + 内联 `<script>` 逐段 `vm.Script` 校验，`app.js`、`watch/admin/judge/super` 全部通过。
- **隔离实例回归**（3 个全新 data 目录）：
  - 路径穿越 4 种写法 → 404；正常静态文件 200。
  - 空实现交卷 → `score=0.0`；再调效率接口 → 409，6 秒后仍 0.0。
  - 判罚 → 0 分；再调效率接口 → 409，仍 0.0。
  - 正确提交（不再由前端触发效率）→ 服务端自动排队 → 最终 `score=100.0, eff=20.0, ready=true`。
  - 重复调用效率接口 → 200「已完成」，分数不变；夹带的 `code` 参数被忽略。
  - 强制结束后再交卷 → 409；已交卷者的 100 分未被覆盖；未写代码者按白卷 0 分。
  - 授予管理员 → 后台 200；撤销后同一 token 立即 401。
  - 封号 → 已登录会话立即 401，重新登录 403；解封后恢复。
  - 观赛代码：未登录 401、未交卷选手 403、观众 200、裁判 200、已交卷选手 200。
  - 后台读讨论区 → 200（修复前 401）。
- **计分曲线**（`codingScoreSeconds`）：39:59→20.0、40:00→20.0、40:30→19.9、60:00→16.0、80:00→12.0、100:00→8.0、119:59→0.0、120:00→0.0，无断崖。

## 三、仍未修 / 需要你后续决定的

1. **观赛折中方案不是绝对防线**：选手另开浏览器、用别的学号登成「观众」仍能看代码。要彻底封住只能「赛中关闭实时代码」或改成裁判/总管白名单，属于产品取舍。
2. **静态扫描仍有盲区**：全限定名 `new java.io.File(...)`、方法句柄/反射变体、把排序藏进字符串再 `Class.forName` 之类，纯文本扫描不可能全覆盖；目前能挡住的是最常见的抄近路写法。
3. **登录无验证码、无限速**，65 个账号初始口令统一 `123456`；密保答案明文存 `state.tsv`。内测阶段可接受，对外网开放前建议补。
4. **裁判/总管 token 没有过期时间**，服务重启才失效；也还没有服务端 logout。已修的是「管理员撤销/封号」两条路径。
5. 前端还有一批 P2 没动（都在审查报告里）：跨账号异步回写的会话代次校验、评论/快捷消息并发去重、后台危险操作按钮的 in-flight 锁、裁判端三个串行轮询的旧响应覆盖、交卷请求期间编辑器仍可编辑。
6. 判题为了拿代码快照会把同一份代码编译两次（正确性一次、效率一次），大场次可以合并，但会牵动两段式交卷的时序，暂未动。
7. `data/` 里现有 7 条 15:58 的「强制结束、按白卷处理」0 分记录，按你的看法保留未清；下一次裁判点「开启比赛」时会照常归档并清空。
